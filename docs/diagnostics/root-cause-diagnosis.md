# Root-cause diagnosis

Root-cause diagnosis is deterministic repository/operator tooling composed through game-owned capabilities and sealed evidence. It does not give AI or the Production application diagnostic authority.

For Skyrim, bounded collectors may build record/asset graphs and resolve proof nodes only from complete winning-record/asset observations under the sealed request and resource limits. Unsupported, malformed, unbound, contradictory, partial, or over-budget results fail closed.

A record-relationship collection binds the sealed baseline plus the profile files that determine the active record graph: `modlist.txt`, `plugins.txt`, and `loadorder.txt`. Every plugin source is independently SHA-256-bound before parsing and profile graph state is hashed again afterward. Volatile MO2 application-window and session preferences in `ModOrganizer.ini` are deliberately excluded because they do not determine record relationships and may change while MO2 is open.

Technical targets originate from explicit structured inputs or deterministic authorized observation, never prose mining.

The terminal public result remains the four-field contract: **Affected mod(s)**, **Mod role(s)**, **Finding**, **Solution**. Confidence cannot resolve the finding by itself.

Any materialized patch/repair specification is inert until a separate supported remediation capability, current proposal, explicit authorization, authorized executor wrapper, verification, and rollback contract exist. Root-cause collection itself must not mutate game/mod state.
